### File Responsibilities

**Entry and shared**

| File | Purpose |
|------|---------|
| `src/worker.js` | Routes `/icons` and `/card`, enforces the rate limit, parses parameters and aliases, downloads the cover image for cards, and calls the appropriate renderer. |
| `src/utils.js` | Shared validators (numbers, booleans, hex colors) and escaping helpers. |

**Icons endpoint**

| File | Purpose |
|------|---------|
| `src/icons.js` | Defaults and limits, SVG layout (`buildSvg`), row/column computation, and rendering each icon with `translate` and an optional rounded clip. |
| `dist/icons.json` | Generated. Each icon's `viewBox` and inner markup. |
| `build-icons.js` | Converts `icons/*.svg` into `dist/icons.json`. |

**Cards endpoint**

| File | Purpose |
|------|---------|
| `src/card/index.js` | Validates options, resolves widget data, and calls `composeSvg()`. |
| `src/card/layout.js` | Sizes, positions, and validators for `size`, `imagewidth`, and `corner`. |
| `src/card/colors.js` | Parses `colour` into one or two hex colors. |
| `src/card/content.js` | Title and description rendering, truncation, and wrapping. |
| `src/card/image.js` | Merge modes: `cut`, `line`, `smooth`. |
| `src/card/image-fetcher.js` | Downloads the cover image and embeds it as a `data:` URI. |
| `src/card/parser.js` | Parses `type:value` widget strings. |
| `src/card/widgets.js` | Measures and renders the five widget types. |
| `src/card/github.js` | GitHub API calls with a 1-hour cache. |

## Request Lifecycle

### Icon Requests (`/icons`)

1. **Rate limit.** The client IP (from `CF-Connecting-IP`) is checked. Over 100 requests per minute per Worker isolate returns `429`.
2. **Parse.** `i` is split on commas, trimmed, lowercased, and empty entries are removed.
3. **Validate.** `size`, `gap`, and `radius` are checked against their ranges, and hex colors are parsed. `perline` is parsed with `parseInt` without a range check — see [Known Internal Limitations](#known-internal-limitations).
4. **Filter.** Names not present in `dist/icons.json` are dropped.
5. **Layout.** `buildSvg()` in `src/icons.js` works out rows and columns:
   - `columns = min(perline || allIcons.length, allIcons.length)`
   - `width  = columns × size + (columns − 1) × gap`
   - `height = rows × size + (rows − 1) × gap`
6. **Render.** Each icon is placed with `translate(x, y)`. With `bg=true`, it is drawn inside a rounded rectangle and clipped to it. With `bg=false`, it is placed directly.
7. **Respond.** An SVG is returned with `Cache-Control: max-age=60`.

### Card Requests (`/card`)

1. **Rate limit.** Shares the counter with `/icons`.
2. **Route and parse.** `worker.js` reads each parameter, using its alias if the full name is missing.
3. **Embed the image.** If `img` is a remote URL, it is downloaded and converted to a `data:` URI. If that fails, the original URL is kept as an external `<image>` reference.
4. **Validate.** `generateCard()` checks every option. The first error stops the request with `400`.
5. **Resolve widgets.** The three widget values are parsed and their data is fetched in parallel. `stars` and `lan` use repo stats, and `version` uses the latest release.
6. **Lay out.** `computeLayout()` gives the card its width, the title and description positions, and the widget baselines.
7. **Compose.** `composeSvg()` draws, in order: gradient background, image, title, `topright` widget, title line, description, `bottomleft`, and `bottomright`. Everything is clipped to a rounded rectangle.
8. **Respond.** An SVG is returned with `Cache-Control: max-age=60`.

> **Order matters:** the cover image is downloaded **before** card validation. An invalid `title` still triggers a fetch of `img`. If you change this order, update [CHANGELOG.md](../CHANGELOG.md) and [SECURITY.md](../SECURITY.md).

## Card Architecture

### Adding a Widget Type

1. Add the name to `KNOWN_TYPES` in `src/card/parser.js`, and write a parse function for its value.
2. If it needs live data, add a branch in `resolveWidgetData()` in `src/card/index.js`, and a fetch function in `src/card/github.js`.
3. Add `measure` and `render` branches in `src/card/widgets.js`.

### Title shortening

The title is shortened when a `topright` widget is present, so it does not overlap the widget. The measured width is estimated by character count — see [Known Internal Limitations](#known-internal-limitations).

## Icons Architecture

### Build Step

`build-icons.js` runs before each deploy (`npm run build`). For every SVG in `icons/`, it:

1. Reads `viewBox` from the root `<svg>`. If missing, it uses `width` and `height`, falling back to `0 0 24 24`.
2. Keeps only the markup inside `<svg>…</svg>`.
3. Prefixes every `id` with the icon name, e.g. `id="a"` inside `javascript.svg` becomes `i-javascript-a`. This prevents ID clashes when several icons share one image. References (`url(#…)`, `href`, `xlink:href`) are updated too.

Icons that cannot be parsed are skipped with a warning.

### Icon SVG requirements

- `viewBox` preferred. If missing, `width` and `height` are used. If both are missing, `0 0 24 24` is used.
- No external references (`<image href="https://…">`, remote CSS, web fonts).
- No `<script>`, event handlers (`onload`, `onclick`), or `<foreignObject>`.
- No embedded base64 data longer than a few KB.
- Clean paths with no unnecessary groups or transforms.

### Adding an Icon (internal steps)

1. Add `yourname.svg` to `icons/`. The name is lowercased, so use lowercase.
2. Confirm the SVG meets the requirements above.
3. Run `npm run build` to verify. The output reports how many icons were generated and any skipped files.
4. Deploy. Only then will the icon appear on the live domain and in `ICONS-LIST.md`.

> **Testing before deploy:** a new icon does not exist on `charmly.read-me.workers.dev` until it is deployed. Test locally with `wrangler dev` (see [CONTRIBUTING → Testing locally](../CONTRIBUTING.md#testing-locally)) or against the `charmly-dev` deployment.

## Caching

| What | Where | How long |
|------|-------|----------|
| Repo stats and release tag | `caches.default` | 1 hour |
| Final card SVG | HTTP header | 60 seconds |
| Final icon SVG | HTTP header | 60 seconds |
| Cover image | Not cached | Downloaded on every request |

## Rate Limiting

- **100 requests per minute per Worker isolate.** The counter is kept in memory inside the isolate, so it is not a global limit. A single client IP can exceed 100/min across isolates.
- Shared between `/icons` and `/card`.
- Over the limit → `429`.

## Known Internal Limitations

- **ID rewriting is regex-based.** `url('#id')` with quotes, and IDs referenced only from `style` attributes, are not rewritten. Those icons can break when they share one image with others.
- **`perline` is not range-checked.** It is documented as 1–50 in `README.md` and `ICONS.md`, but `parseInt` accepts any value. `0`, negative, and non-numeric values fall back to one row; large values are capped at the icon count. Documented behavior and code must be aligned.
- **`size`, `gap`, `radius` accept decimals.**
- **Text width in cards is estimated** by character count, about 0.55 em per character. Wide letters can overflow, and narrow ones leave gaps.
- **Card height is fixed** at 250 px.
- **Cover images are limited to 200 KB.** Only PNG, JPEG, WebP, and GIF are embedded. SVG and other formats are kept as an external `<image>` reference, which **will not render inside an `<img>` tag** (the normal README case).
- **GitHub data uses unauthenticated requests.** A shared rate limit applies. When exhausted, live widgets fall back to placeholders.
- **Widget values cannot contain `:`** — a badge like `Note: draft` is rejected
